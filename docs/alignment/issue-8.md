## Recommendations (advisory)

1. **(Low, #40)** Either move menu images to `next/image` (adding the Convex deployment host to `images.remotePatterns`, and noting that `quality` outside `images.qualities` is coerced to 75), or record in `menu-tabs.tsx` why the raw `<img>` is deliberate — Convex signed URLs are bearer URLs whose only revocation is deleting the file, and the repo's B7 gallery made the same call. Keeping both surfaces on the same decision is the important part.
2. **(#49, highest-risk unverified claim)** Do not treat the order id as a security boundary without a decision. Options, in order of preference: (a) add `orders.accessToken` (or reuse the `bookings.cancelToken` shape) returned once at submit and required by `getOrderStatus`; (b) keep the id but strengthen the doc comment so it is an explicit accepted v1 risk rather than a claim that ids are unguessable. Option (a) also satisfies `convex/AGENTS.md`'s "token links" convention.
3. **(#50)** Keep verify → write → delete ordering. It is safe under either transaction semantic and the orphan-on-failure window is bounded by the image policy.
4. **(#51)** Consider an explicit projection in `listForBusiness` (`_id`, `groupId`, `name`, `description`, `price`, `nutrition`, `customizationOptions`, `isAvailable`, `ordering`, `imageUrl`) instead of `...item`. It removes internal ids from the public payload and makes the contract reviewable.
5. **(Hardening, not a doc finding)** `submitOrder` accepts `selections` up to Convex's array ceiling (8192) and validates each element in a loop. Add a small cap (e.g. `selections.length > 32` → `ConvexError`) so an anonymous caller cannot buy CPU. Also note there is still no application-layer rate limit (#25), which the docs confirm Convex does not provide.
6. **(Version gaps #41-#48)** Bump `convex` → 1.47.0, `next` → 16.4.2, `react`/`react-dom` → 19.3.1, `tailwindcss` → 4.3.3, `@clerk/nextjs` → 7.9.17, `vitest` → 5.x and `typescript` → 7.x at the next dependency pass. The TypeScript and Vitest majors are the only ones that need a migration read; none of the APIs used here is deprecated in the installed versions.
